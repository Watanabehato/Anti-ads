# 隐私说明（Anti-ads）

本文说明 Anti-ads 在设备上处理哪些数据、数据留在哪里，以及**明确不收集**什么。
本应用是纯本地工具：没有服务器端，也没有任何联网组件。

## 1. 不收集、不上传

- **不申请 `INTERNET` 权限**（管理端 APK 与诊断 APK 的合并 Manifest 中都没有该权限，可由 `aapt2 dump badging` 复核）。
- 不上传包名列表、界面文本、点击记录、传感器读数、设备标识或使用统计。
- 不接入广告、统计、崩溃上报或第三方 SDK。
- 不做 Root 提权、不改 SELinux、不自动配置框架作用域。

## 2. 设备上保存什么

| 数据 | 位置 | 用途 |
| --- | --- | --- |
| 防护配置（总开关、两种模式开关、每包开关与所选传感器类型） | 应用私有目录 `filesDir/protection-config-v1.json`（原子写入） | 决定对哪些应用生效 |
| 运行状态（服务是否连接、最近一次动作是否被系统接受、最近报告） | **内存**，不写磁盘 | 界面显示真实状态；报告在重启后不还原为“在线” |
| Hook 进程自报（安装状态、读取状态、计数） | 宿主进程内存（Provider 接收，最多保留 8/包、128 条） | 展示“是否观察到注入”，不做跨重启持久化 |

界面文本、输入内容、节点树全文、传感器读数**不存储**：无障碍侧只保留最近一次规则/包/时间/动作返回值，
且文本字段有长度上限。日志不打印原始配置或界面文本。

## 3. 跨进程读取的最小化

目标应用进程读取配置时，只能拿到**它自己那个包**的最小策略（是否启用、允许拦截哪些传感器类型、配置版本号）：

- 没有任何“读取全部配置”“写入配置”“列出所有已配置应用”的远程接口；
- 每次读取都在服务端用 `Binder.getCallingUid()` + `PackageManager.getPackagesForUid` 现场鉴权，
  请求参数里的包名**不被信任**，只作提示；
- 共享 UID 多包、isolated 进程、无法枚举包名的调用一律拒绝；
- 未授权/不可达/配置损坏时，目标进程按“放行”处理，不会因此中断目标应用功能。

配置写入只发生在管理端进程内部（本地 Repository），不经过 exported Provider。

## 4. 无障碍数据的处理边界

- 只在系统绑定服务后监听 `TYPE_WINDOW_STATE_CHANGED`/`TYPE_WINDOW_CONTENT_CHANGED`；
- 单次遍历最多 300 个节点、深度 20、时间预算 8ms，达到任一上限即放弃本次判断（`traversalComplete=false`）；
- 出现任何可编辑/密码节点即整窗放弃；锁屏、系统 UI、输入法、桌面、宿主自身等敏感窗口不处理；
- 不截图、不录屏、不做坐标点击、不执行返回/Home、不自动同意权限或支付。

## 5. 卸载与数据清除

卸载应用会删除其私有目录中的配置文件；内存中的状态随进程结束消失。
诊断 APK 的数据同样只存在自身私有目录（且已显式禁止云备份与设备迁移）。
详见 [docs/install.md](install.md) 的“停用与卸载”一节。

## 6. 已知限制（与隐私相关的真实边界）

- 目标进程自报的报告**只是自报**：同一 UID 内无法对“自己发起的调用”和“框架注入的调用”做密码学区分，
  因此界面把它标注为“进程自报”，不作为授权依据。
- 系统级 Root 环境本身可以读取设备上的一切；本应用的“不采集”指本应用自身不采集、不外传，
  不代表能在已 Root 设备上提供对抗同 UID 恶意代码的隔离。
