# Anti-ads v0.1.0 预览版 —— Android 10+ 摇一摇广告防护

- **版本**：v0.1.0（pre-release 预览版，不是生产发布）
- **日期**：2026-09-21
- **定位**：Android 10（API 29）及以上的摇一摇广告防护工具——**免 Root 的保守“跳过”点击** + **可选的 Root/LSPosed 传感器回调拦截**（增强模式）。
- **许可**：[MIT](https://github.com/Watanabehato/Anti-ads/blob/main/LICENSE) ｜ 仓库：<https://github.com/Watanabehato/Anti-ads>

## 变更内容（首个可构建预览）

- **五模块工程**：`:core`（纯 Kotlin 判定/配置）、`:app`（管理端，同时是 LSPosed 模块）、`:accessibility`（无障碍服务）、`:hook`（LSPosed 传感器拦截）、`:probe`（独立诊断 APK）。minSdk 29 / compile+target 35。
- **中文管理界面**：总开关、两种模式全局开关、按应用开关与传感器类型选择；首页**分列真实状态**（系统设置授权 vs 服务实际已连接、进程自报报告与过期、能力边界说明），不做“已全面保护”式合成结论。
- **配置持久化与受控只读 Provider**：AtomicFile + revision 比较提交；Provider 只有两个只读 `call`，每次 `Binder.getCallingUid()` 现场鉴权、只返回调用方本包最小策略，**无任何远程写接口**。
- **无障碍跳过引擎与误触防护**：只处理应用窗口/非锁屏/非敏感包；要求**独立可见的广告上下文节点** + 跳过文案精确正则 + 右上角几何（面积 ≤12%、中心 X ≥65%、中心 Y ≤25%）；窗口内出现输入/密码节点整窗放弃；同窗口只尝试一次、同包冷却、执行前复核配置 revision 与节点状态。
- **LSPosed Java 传感器分发拦截**：仅定位 `SystemSensorManager$SensorEventQueue.dispatchSensorEvent`；1s 逻辑读取期限 + 5s 租约，**失联/坏响应/时钟回退一律放行**；不改写读数、不注销原监听、不覆盖 native/DirectChannel。
- **诊断 APK `probe`**：真实传感器计数、5 个广告正反例场景、返回后**显式重新采样**、debuggable 下节流写 `files/probe-diag.json`；不申请 INTERNET。
- **文档与 CI**：`docs/` 下 18 份中文文档（需求、架构、接口合同、各模块实现、安装、隐私、验证报告、交付说明等）；GitHub Actions 每次推送运行五模块单测 + 四模块 lint + 组装四个 APK 并上传 `debug-apks`。

## 已验证范围（Android 10 / API 29 官方模拟器，项目内 AVD）

- **授权与撤权**：通过系统 UI 授权 → 返回首页正确显示“已授权且已连接”；撤权后准确回落（双向核对系统值、Bound 状态与截图）。
- **三层开关独立生效**：总开关 / 模式开关 / 每包开关各自关闭均停止动作。
- **广告正例 4 轮**：诊断样例页“广告 + 右上角跳过”被正确处理；**5 类反例零点击**（无广告上下文、不可点击、按钮在下部、含输入框、未知场景）。
- **Provider 身份与权限**：真实应用 UID 只读策略读取成功；**shell（UID 2000）全部被拒绝**；无写入口。
- **probe 生命周期**：离开页面停止采样，返回后按钮/状态正确且**只能由用户显式重新开始**（无自动重注册）；诊断快照可解析、节流最小间隔约 1s、暂停态会强制写一次。
- **构建与测试**：**298 项 JVM 单测 0 失败**；**lint 0 error**（仅两条有明确理由的设计性 warning）；强制重跑（`--rerun-tasks --no-build-cache`）产出的 APK 与**设备实际安装件逐字节一致**。

## 已知限制与未验证（请务必阅读）

- **增强模式（Root/LSPosed）未实测**：本版没有在真实 Root/LSPosed 设备上验证注入、作用域与首次注入流程；**仅安装 APK、仅授权 Root、仅打开开关都不等于生效**。
- **Hook 5 秒租约未做设备观测**：仅覆盖 JVM 边界用例（`now = expires` 必放行等）；真实首个传感器事件到达时间取决于硬件采样周期。
- **未覆盖**：NDK/JNI 自建传感器读取、`SensorDirectChannel`、厂商私有接口、共享 UID、隔离进程、工作资料。
- **未实测的系统**：API 30+/33+/35+（包可见性、受限设置、WindowInsets）与真机/OEM 机型。
- **无障碍模式的固有边界**：不阻断传感器、不阻止原生点击；自绘/游戏画面、不可访问 WebView、无语义节点、按钮不在右上角时**不会处理**，也无法保证比广告跳转更早。
- **APK 跨环境构建不可复现**：CI 产物与设备核对过的本组**字节数相同但 SHA-256 不同**；CI artifact 不能当作设备验证过的那组产物（详见 `docs/delivery.md` §3.2）。
- 本版**只保证“源码可构建 + 上述有限设备场景”**，不承诺覆盖所有应用、所有系统版本或所有广告形式。

## 安装提要

完整步骤见仓库文档 [docs/install.md](https://github.com/Watanabehato/Anti-ads/blob/main/docs/install.md)。

1. 安装 `app-debug.apk`（管理端，同时是 LSPosed 模块）；可选安装 `probe-debug.apk`（诊断）。
2. **免 Root 模式**：打开首页 → 跳转系统无障碍设置 → **手动启用**本应用服务 → 返回后确认“服务实际已连接”；在应用列表中为具体应用打开“无障碍跳过”开关（默认全关）。
3. **增强模式**：需自备兼容的 Root + LSPosed 框架 → 激活模块 → 勾选作用域（建议先只勾 `com.antiads.probe`）→ **停止并重新打开目标应用** → 在管理端打开增强模式与该应用的传感器开关。
4. **停用与恢复**：关闭开关后无障碍立即停止排队并在点击前重读配置；增强模式约 2–3 秒生效、**最迟 5 秒**租约放行；撤权立即断开；**完全移除注入需重启目标进程**；卸载前建议先关闭开关。
