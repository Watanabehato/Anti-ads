# Anti-ads 需求与验收基线

本文与 `architecture.md`、`contracts.md` 一起构成 v1 开发合同。目标是 Android 10（API 29）及以上的中文摇一摇广告防护工具，交付可构建源码、管理 APK、独立诊断 APK、真实测试证据与公开仓库 `Watanabehato/Anti-ads`。不存在“普通应用无条件禁止所有其他应用读取传感器”的 Android 公共接口；产品不得宣称全面覆盖。

## 1. 产品范围

- 免 Root 模式：用户主动启用无障碍服务，并为具体应用开启保守的广告跳过规则；只在可访问的应用窗口里点击明确的“跳过”按钮。不阻断传感器、不阻止所有摇动触发、不保证能在广告跳转之前处理。
- Root/LSPosed 模式：设备已有兼容的 Root 与注入框架，用户在管理器激活模块并勾选具体应用作用域；拦截所选应用进程中已识别的 Java 传感器事件分发路径。仅安装本 APK、仅授予 Root 或仅开启产品开关均不等于模块生效。
- 两种模式允许同时使用；总开关、两种模式的全局开关、每包模式开关均独立存储，实际策略取交集。首次安装全部关闭，应用名单为空。
- 每包传感器集合默认为加速度计（1）、陀螺仪（4）、重力（9）、线性加速度（10）、旋转矢量（11）。可分别关闭；运动、导航、游戏、计步等正常功能可能受影响。不得默认阻断光线、距离、步数或全部传感器。
- 只包含本地管理与诊断；不申请 INTERNET、不上传包列表/界面内容/传感器数据，不自动提权、修改 SELinux、安装 Root 或配置框架作用域。

## 2. 平台、权限与覆盖边界

| 项目 | 前置条件与实际能力 | 必须展示的限制 |
| --- | --- | --- |
| 管理端 | minSdk 29；用户本地安装 APK | API29+ 是安装与公共 API 基线，未来 Android/OEM 版本仍需验证 |
| 无障碍 | 系统设置中手工授权；服务已连接；目标包允许；全局开关有效 | 自绘/游戏画面、不可访问 WebView、无语义节点、按钮出现在安全过滤区以外均可能不处理 |
| Android 13+ 侧载 | 系统可能出现“受限设置”，需要用户在应用详情允许相关设置 | 不绕过系统限制，不假称已自动授权；不同安装源/OEM 路径不同 |
| LSPosed | 用户已有兼容框架、模块已激活、目标包在作用域、目标进程重启完成注入 | 原始 LSPosed 官方 README 标注 Android 8.1～14；本项目 API29～34 可作为框架候选范围，仍须设备实测 |
| Android 15/API35+ Hook | 使用明确支持对应 Android 的维护版框架并逐版本验证 | 不根据 minSdk/targetSdk 推定支持；未测时显示“框架兼容性未验证” |
| Java 传感器 | 目标使用可定位的 SystemSensorManager 事件分发实现 | 隐藏类、方法与字段受 Android/OEM 影响；定位失败必须放行并报告不支持 |
| Native/Direct Channel | 不属于 v1 拦截范围 | NDK ASensorManager、JNI 自建读取、SensorDirectChannel 共享内存、厂商私有接口、远端/其他进程推断不保证被拦截 |
| 多进程/多用户 | 只保护真正注入且能认证读取配置的同用户进程 | 隔离进程、工作资料、分身、共享 UID/混合包进程需要单独验证；不保证自动覆盖 |

系统对后台传感器和高采样率的限制不是本产品的跨应用拦截权限。官方传感器文档描述 Android 9 的后台限制和 Android 12 针对部分传感器的采样率限制，不能据此声称所有传感器不可被读取。

## 3. 中文交互与状态真实性

管理首页至少显示：总开关、两种模式开关、已配置应用数量、无障碍“系统已启用/实际已连接”两个事实、目标 Hook 的最近报告与时间、未测试的覆盖范围。应用列表默认查询可启动应用，支持按包名手工添加；Android 包可见性导致列表不完整时解释原因。无需申请 QUERY_ALL_PACKAGES。

每包详情提供无障碍跳过开关、传感器防护开关、传感器类型选择和操作影响提示。设置保存成功仅表示持久化成功；界面必须区分“已配置”“已观察到 Hook 安装”“最近发生拦截”“诊断实测通过”。没有进程报告显示“未观察到注入”；不可写死“已激活”、靠 su 存在判断激活、或把异常转成成功。

用户可跳转系统无障碍设置、打开兼容框架管理器的可用入口/安装说明、打开诊断应用；找不到管理器时显示可操作的中文说明。所有授权由系统/框架完成。不得把需要授权的页面伪装成产品内可一键授予。

## 4. 安全策略、停用与恢复

1. 所有模式默认关闭；仅明确允许的包生效。系统 UI、宿主自身、输入法、桌面、锁屏及包含可编辑/密码节点的窗口禁止自动操作。具体规则见合同。
2. 不执行坐标点击、滑动、返回/首页、自动同意权限、支付或安装确认。无障碍只执行通过全部约束的节点 ACTION_CLICK。无法确认时跳过处理。
3. 总开关/模式开关/每包开关关闭后，无障碍应取消排队动作并在点击前重读配置。Hook 以异步刷新接收关闭，正常情况下活跃进程约 2 秒发起刷新，加上最多 1 秒有效读取时间约 3 秒内更新；配置租约最多 5 秒，超时无条件放行。停止 LSPosed 注入本身仍需要目标进程重启。
4. Hook 不更改传感器列表、不伪造注册成功、不改写读数，不主动注销应用监听器；丢弃 Java 回调的同时保留原注册关系，关闭后未来回调可恢复。应用因超时自行注销的情况需要它重新注册或重启。
5. Provider 不可达、未授权、配置损坏、版本未知、注入失败或隐藏签名不匹配均不阻断目标传感器。错误需能在诊断页解释。
6. 完整配置只供宿主同 UID 读取/修改；外部目标仅能读本 UID 所属目标包的最小策略。外部诊断报告不具备配置写权限，且被视为进程自报信息而非可信框架证明。

## 5. 验收场景与版本矩阵

所有证据记录 commit、APK SHA-256、设备型号、Android/API、安全补丁、ABI、Root/框架名称及版本、目标版本、作用域、操作步骤与预期/实际结果。不能执行的条目标注“未测试/阻塞原因”，不能用单元测试结果冒充真机 Hook 成功。

| 环境 | 必查项目 | 交付时的结论规则 |
| --- | --- | --- |
| JDK17 主机 | 五模块编译、core 单测、Android 单测/lint、两个 APK 打包 | 运行命令与退出码必须保留；首次工具链安装由骨架负责人执行 |
| API29 Android10 模拟器/真机 | 安装启动、全关默认、无障碍正反例、启停恢复、诊断传感器基线 | 未提供设备即未测，不能声称最低版本已验证 |
| API30～32 | 包可见性、进程重启、服务重连、配置恢复 | 至少一档实测；其余逐版本记录未测 |
| API33～34 | 受限设置引导、无障碍生命周期、目标关闭恢复 | 至少一档实测；受限设置行为按安装源记录 |
| API35+ | target35 布局与系统边到边显示、无障碍可用性、侧载限制 | 每个已测试 API 单列；Hook 框架另行判定 |
| API29～34 + 兼容 LSPosed | 作用域开/关、首次注入、按包/类型选择、失联放行、多进程 | 没有真实 Root 设备不得宣称运行通过 |
| API35+ + 维护版框架 | 明确版本组合的 Java 回调定位与恢复 | 不自动继承原始 LSPosed 兼容性；缺少设备即实验性未验证 |

最少测试集合：

- C01 默认配置和损坏配置均不点击、不丢传感器回调；JSON 往返、版本拒绝、包名/传感器校验、revision 冲突明确失败。
- A01 诊断应用的广告样例：屏幕右上角、可点击“跳过 5 秒”，独立“广告”标签；只点击一次，记录实际 performAction 返回值。
- A02 非广告页面含“跳过”、广告文案但无按钮、下方/不可见/不可点击按钮、输入框/密码框、锁屏、包名不符、窗口切换、配置刚停用、连续内容事件全部不误触。
- A03 服务授权后实际连接、撤权、进程重建、快速切换目标、节点已失效、超量节点与节流；无死循环、ANR 或后台持续扫描。
- H01 probe 基线能接收 Java 传感器事件；启用后被选类型显著停止、未选类型持续；关闭后未来事件恢复。真实设备有传感器并先完成基线才可判定成功。
- H02 全局关闭/模式关闭/包关闭/空集合/不在作用域/模块未激活/其他应用不受影响；重新启动目标与配置热更新的差异可见。
- H03 Provider 停止、读取拒绝、坏 JSON、未知 schema、读取超时，最多 5 秒旧策略过期放行；回调线程不进行 Binder/文件/网络操作。
- H04 Android/OEM 隐藏方法不存在或参数不匹配时保持原始调用，报告 UNSUPPORTED/ERROR；模块未报告不可显示已生效。
- S01 未授权 UID 不能读取别包策略/完整配置、写配置或伪造别包报告；批量报告受限，计数非信任边界。
- P01 probe 无 INTERNET 权限；正例/反例广告测试窗口独立；无传感器、监听失败、停止采样分别可见。Direct Channel/Native 路径标注不覆盖，不把无回调自动判为被拦截。
- R01 保存配置后杀死/重启管理端恢复；撤销服务授权、停用模块、关闭开关、卸载宿主时恢复边界有中文说明。

最终 QA 可以给出“源码/构建通过，设备项未测”的分层结果，但交付必须原样披露限制。存在误触、配置越权、关闭失效、伪造生效状态或不可构建时不能判定产品通过。
