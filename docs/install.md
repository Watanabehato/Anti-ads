# 安装、启用、停用与卸载指南

适用对象：Android 10（API 29）及以上设备。管理端 APK（`app-debug.apk`）同时充当 **LSPosed 模块**；
诊断 APK（`probe-debug.apk`）只用于验证与实验，不参与防护。

> 本页描述的步骤已在项目 API29 模拟器（AVD `AntiAds_QA_API29`，serial `emulator-5580`）上按序列实际执行：安装、系统 UI 授权与撤权、应用选择与每应用开关、probe 采样/暂停/返回、Provider 真实 UID 读取（证据见 [独立 QA 报告](verification.md) 与 `docs/qa-evidence/t17-bea37e8/`）。
> **仍未在真机、Root/LSPosed 设备与 API30+ 上逐条执行**；这些环境的结论不得由本页或模拟器结果推断。设备实测结论以 QA 的执行记录为准。

## 1. 安装

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r probe/build/outputs/apk/debug/probe-debug.apk   # 可选：诊断
```

- Debug APK 使用调试签名，**不是生产发布包**。
- Android 13 及以上可能出现“受限设置”：需要在系统里允许该来源应用的相关设置后，才能授予无障碍服务；
  本应用不会绕过该系统限制，也不会伪装成一键授权。
- 两个 APK 都不申请 `INTERNET`，也不申请 `QUERY_ALL_PACKAGES`。

## 2. 免 Root 模式（无障碍跳过）

1. 打开管理端首页，确认**总开关**处于打开状态。
2. 点击“打开系统无障碍设置”，在系统列表中找到本应用的服务并手动启用（系统会显示该服务可读取屏幕内容的提示）。
3. 返回管理端：首页会分别显示两个**不同**的事实——
   - “系统设置中已启用”（来自 `AccessibilityManager` 的启用列表）；
   - “服务已连接”（来自服务自身回调 `onServiceConnected`）。
     只有第二个为真时才会实际尝试点击。
4. 在“应用列表”里勾选目标应用（按可启动应用列表，或手工输入包名），并在应用详情中：
   - 打开该应用的“无障碍跳过”开关；
   - 确认该应用出现在列表中且两个开关符合预期（默认都是关闭的）。
5. 打开目标应用，进入有广告的页面。命中条件为：窗口是应用窗口、非锁屏、非敏感包、
   窗口中存在独立的“广告”上下文节点、候选按钮文案完整匹配“跳过/跳过 5 秒/5 秒跳过/Skip/Skip ads 5 s”等、
   按钮位于屏幕右上角区域、且窗口进入不超过 10 秒。

界面会显示“已发送跳过点击”，这**只表示系统接受了动作**，并不等于广告确实消失；是否能跳过要由目标页面自身证明。

## 3. 增强模式（Root / LSPosed 传感器拦截）

前提：设备已有兼容的 Root 与 LSPosed 兼容框架，并且**模块已激活、目标包在作用域内、目标进程已重启**。
仅安装 APK、仅授予 Root、仅打开本应用开关都**不等于**模块生效。

1. 在框架管理器中启用 Anti-ads 模块（安装的即管理端 APK）。
2. 勾选作用域：建议先只勾选诊断应用 `com.antiads.probe`（模块自带建议作用域即为它）；其他应用由用户自行添加。
3. 停止并重新打开目标应用（必要时按框架说明重启设备）。管理端**不会**自动强停其他应用。
4. 在管理端打开总开关与“增强模式”全局开关，并在目标应用详情中打开“传感器防护”，选择要拦截的类型
   （默认：加速度计、陀螺仪、重力、线性加速度、旋转矢量）。
5. 回到管理端查看该应用的状态事实：是否收到目标进程的自报、安装状态（`INSTALLED`/`UNSUPPORTED`/`ERROR`）、
   配置读取状态与最近报告时间。没有报告时应显示“未观察到注入/尚未报告”，而不是“已激活”。

启用增强模式会影响目标应用对相关传感器的正常使用：运动、导航、游戏、计步等场景可能受影响；
不开关类型集合即可放行全部回调。

## 4. 停用与恢复

| 操作 | 生效时间与范围 | 备注 |
| --- | --- | --- |
| 关闭总开关 / 全局模式开关 / 每包开关 | 无障碍：立即取消排队动作并在点击前重读配置；Hook：最多约 2 秒刷新 + 1 秒读取期限，租约最迟 5 秒后全部放行 | 关闭后**未来的** Java 回调恢复；不补发历史事件 |
| 在系统设置中撤销无障碍授权 | 服务立即断开，状态变为未连接 | 不需要重启设备 |
| 在框架中关闭模块或调整作用域 | 已注入进程中的代码可能继续工作到进程重启为止 | **请先关闭产品内的开关**，再改框架设置 |
| 完全移除注入 | 需要停止并重新启动目标应用（或重启设备） | 本应用不执行强停 |
| 卸载管理端 APK | 配置随私有目录删除；目标进程租约到期后放行 | 已注入进程需重启才彻底恢复 |

目标应用若因长时间收不到回调而自行注销监听器，重新注册或重启后恢复——这属于目标应用自身行为，本应用不代为处理。

## 5. 诊断与自检（可选）

```bash
# 真实传感器计数与“同一次注册”实验页
adb shell am start -n com.antiads.probe/.MainActivity

# 广告样例（正例）
adb shell am start -n com.antiads.probe/.AdFixtureActivity --es scenario ad_positive
# 反例：无广告上下文 / 不可点击 / 按钮在下部 / 页面含输入框
adb shell am start -n com.antiads.probe/.AdFixtureActivity --es scenario no_ad_label
adb shell am start -n com.antiads.probe/.AdFixtureActivity --es scenario non_clickable
adb shell am start -n com.antiads.probe/.AdFixtureActivity --es scenario bottom_button
adb shell am start -n com.antiads.probe/.AdFixtureActivity --es scenario editable_window

# 诊断日志（进程自报；`AntiAdsHook.Diag` / `AntiAdsProbe.Diag` 为稳定前缀）
adb logcat -s AntiAdsHook.Diag AntiAdsProbe.Diag
```

样例页只产生本地测试内容，不注册传感器、不写配置、不做敏感动作。

## 6. 常见问题

| 现象 | 可能原因 |
| --- | --- |
| 首页显示“已启用”但一直不动作 | 服务尚未“已连接”；或总开关/该应用开关未开；或窗口在 10 秒窗口期之外 |
| 有广告但没有点击 | 缺少独立的“广告”上下文节点；按钮不在右上角 25% 区域；文案不是精确的“跳过”样式；页面含输入框；窗口遍历超限 |
| 增强模式显示“读取成功但拦截不支持” | 目标进程内无法定位预期的 Java 分发方法（隐藏类/方法形状变化），此时**保持原始行为** |
| 增强模式没有任何报告 | 模块未激活、作用域未包含该包、目标进程未重启，或该进程没有传感器流量 |
| 关闭开关后仍短暂生效 | Hook 侧最多 5 秒租约（正常约 2～3 秒）；完全移除注入需要重启目标进程 |

## 7. 明确不承诺

- 不承诺覆盖所有应用、所有系统版本、所有广告形式；不承诺一定能在广告跳转前处理。
- 不覆盖：NDK/JNI 自建传感器读取、`SensorDirectChannel`、厂商私有接口、隔离进程/工作资料/共享 UID 多包场景。
- 设备相关结论一律以 QA 的真机执行记录为准；源码可编译、单测通过、lint 干净都不代表设备上有效。
